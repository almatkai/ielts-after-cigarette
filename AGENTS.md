# Ветки и выборочный выпуск

- Перед правками проверь `git rev-parse --show-toplevel`, текущую ветку и `git status`. Работай только в выбранном checkout/worktree; соседние деревья не меняй.
- Одна задача — отдельная ветка `feat/<task>`, `fix/<task>` или `chore/<task>`. Новые независимые задачи начинай от актуального `origin/main`, а не от `dev`: в `dev` могут быть изменения, не предназначенные для продакшена. Получи актуальные refs через `git fetch origin`; при недоступном remote согласуй использование локальной базы.
- Если уже находишься в ветке этой задачи, продолжай в ней. При несвязанных незакоммиченных изменениях сначала согласуй их судьбу; не смешивай задачи, не сбрасывай и не переносись в другое рабочее дерево автоматически. Зависимую ветку от другой feature-ветки создавай только по явному согласованию.
- Коммиты делай в ветке задачи. Слияние в `dev` выполняй по просьбе пользователя; сохраняй feature-ветку для отдельного выпуска. В `dev` и `main` напрямую разработку не веди.
- Продакшен (`main`) получает только явно выбранные и одобренные пользователем feature/fix-ветки через отдельные PR. Перед выпуском проверь полный diff и список коммитов относительно `main`, включая зависимости: в них должна быть только согласованная задача.
- Не сливай `dev` целиком в `main` и не используй `dev` как источник релизного PR: так экспериментальные и ненужные функции могут попасть в прод. Push, merge и deploy в прод требуют отдельного явного разрешения пользователя.
